## 1. Предобработка фонетических данных

### 1.1. Артефакты

Из разметки `.TextGrid` (корпус RUSLAN, 22 199 предложений, папка `data/RUSLAN_22050_align_v2/`) подготовлены четыре файла:

| Файл | Назначение | Строк | Уникальных единиц |
|---|---|---|---|
| `data/tokens_phones.csv` | обучение G2P (без `<SIL>`) | 245 939 | 21 281 предложение |
| `data/tokens_phones_sil.csv` | метаданные для акустической модели (с `<SIL>`) | 305 350 | 59 411 `<SIL>` |
| `data/lexicon.csv` | словарь произношений по train | 41 839 | 41 131 слово |
| `data/russian_mfa.dict` | оригинальный MFA-словарь | 160 509 | 153 486 слов |

### 1.2. Методика

- **Сопоставление слов и фонем** — по перекрытию интервалов: фонема принадлежит слову, если её центр попадает в интервал слова. Это устойчивее к несовпадению границ, чем сравнение по краям.
- **Train/test split** — `id % 5 == 0 → test` (правило из лабы 2). Проверено: нарушений нет, 19.9% токенов в test.
- **Инвентарь фонем** — 56 символов: 55 целевых из `common/phones_mfa.txt` + служебная метка `spn`. Никаких посторонних фонем в корпусе нет.
- **Словарь `lexicon.csv`** построен **только по train-части**. Пересечение с test-only словами равно **0** — утечки данных нет.

## 2. Разведочный анализ фонемного инвентаря

### 2.1. Состав и частоты фонем

В train-части корпуса **56 уникальных символов**: 55 целевых фонем и служебная метка `spn`. Полное совпадение с целевым списком `common/phones_mfa.txt` (без учёта `<SIL>`). Ни одной пропущенной фонемы нет.

Наблюдаемые фонемы близки к IPA, но используют **фонетический набор MFA** — например, зубные `t̪`, `d̪`, `n̪`, `s̪`, `z̪`, аффрикаты `tɕ`, `tʂ`, `dʐ`, `t̪s̪`, редуцированные гласные `ɐ`, `ə`, `ɪ`, `ʊ`.

Распределение фонем по частоте имеет ожидаемую форму: длинный «хвост» редких фонем, типичные для русской речи гласные и согласные в топе.

### 2.2. Длительности фонем

Длительности извлечены из оригинальных TextGrid'ов (выборка 3 000 файлов, ~100 тыс. вхождений). В G2P они **не используются** — их моделирует акустическая модель (лаба 4).

**Ключевые значения (mean ± std):**

| Группа | Примеры | Mean, мс |
|---|---|---|
| Ударные гласные | `a`, `o`, `e`, `i`, `u`, `ɛ`, `æ`, `ɵ` | **102 ± 47** (92–113) |
| Взрывные согласные | `p`, `t̪`, `k`, `b`, `d̪`, `ɡ` и мягкие пары | **96 ± 33** (80–122) |
| Аффрикаты | `t̪s̪`, `tɕ`, `dʐ`, `tʂ` | **135–171** |
| Щелевые | `ɕ`, `ʂ`, `sʲ`, `ç` | **130–168** |
| Редуцированные гласные | `ɪ`, `ʉ`, `ə`, `ɐ`, `ʊ`, `ɨ` | **22–75** |

**Наблюдения:**

1. Длительности соответствуют артикуляционным ожиданиям: аффрикаты и щелевые длиннее взрывных, ударные гласные длиннее редуцированных.
2. **Палатализация удлиняет согласные**: мягкие пары в среднем на 10–40 мс длиннее твёрдых (`tʲ` 122 мс против `t̪` 84 мс).
3. Вариативность велика (std 30–50 мс у большинства фонем) из-за контекста: ударение, позиция в слове, скорость речи.
4. Есть outliers — например, `ɪ` со средним 22 мс (артефакт разметки MFA, «сжимает» редуцированные гласные).

### 2.3. Редкие фонемы

6 фонем имеют **менее 500 вхождений** в train-части:

| Фонема | Вхождений | % | Что это |
|---|---|---|---|
| `ç` | 461 | 0.042 | глухая мягкая `хь` |
| `tʂ` | 259 | 0.023 | твёрдая `ч`/`ш` (заимствования) |
| `dʐ` | 189 | 0.017 | звонкая аффриката |
| `ɣ` | 25 | 0.002 | звонкая `х` (южнорусские говоры) |
| `ʑ` | 16 | 0.001 | мягкая звонкая `ж` |
| `d̪z̪` | **1** | 0.000 | звонкая `ц` (в русском отсутствует) |

**Решение:** оставить все фонемы в инвентаре.

**Обоснование:**
1. Целевой инвентарь `common/phones_mfa.txt` фиксирован заданием и не может быть изменён.
2. Суммарный вклад редких фонем в PER ничтожен: даже при 100% ошибке PER вырастет на ~0.02% — на порядок меньше порога 0.025.
3. Для самой редкой фонемы (`d̪z̪`, 1 вхождение) любая стратегия объединения или удаления не даст измеримого эффекта.

### 2.4. Приведение инвентаря к целевому

Сравнение наблюдаемого инвентаря с `common/phones_mfa.txt`:

| Метрика | Значение |
|---|---|
| Фонем в корпусе | 56 |
| Целевых фонем (без `<SIL>`) | 55 |
| Пересечение | **55** |
| Лишние в корпусе | `spn` (служебная метка) |
| Пропущенные | 0 |

**Приведение не требуется**: все фонемы корпуса уже целевые. `spn` — не фонема, а метка MFA (speaking noise); она исключается при обучении G2P и подсчёте метрик, согласно заданию. `<SIL>` присутствует только в `tokens_phones_sil.csv` и проходит через G2P без изменений.

## 3. OOV-анализ

| Метрика | Значение |
|---|---|
| OOV train к `russian_mfa.dict` | 12 588 / 41 610 = **30.25%** |
| OOV test к `russian_mfa.dict` | 4 033 / 17 192 = **23.46%** |
| **OOV test к train** | 5 622 / 17 192 = **32.70%** |

**Ключевой вывод:** **треть тестовых слов не встречается в train**. Это основная сложность задачи: G2P должен уметь транскрибировать незнакомые слова, а не только подставлять произношения из словаря.

Именно для этого в архитектуре G2P предусмотрен отдельный OOV-модуль (правила + ML), и именно по нему задание ставит отдельный порог PER ≤ 0.20.

## 4. Корректность разметки на проблемных примерах

Из 22 199 размеченных предложений лаба 1 отбраковала **918 (4.13%)**. Проверка показала: все 918 отсутствуют в `metadata_RUSLAN_22200_normalized.csv`, то есть действительно не прошли нормализацию.

**4.1 Анализ токенов в оставшихся 21 281 предложении:**

| Тип | Количество | % | Вывод |
|---|---|---|---|
| Цифры | 0 | 0% | числительные переписаны словами |
| Латиница | 0 | 0% | заимствования записаны кириллицей |
| Аббревиатуры (ВЕРХНИЙ РЕГИСТР) | 0 | 0% | развёрнуты или отфильтрованы |
| Сокращения с точками (`т.е.`) | 0 | 0% | — |
| Неразрывные дефисы (`что‐то`) | 2 119 | 0.86% | нормальные слова, нужна нормализация дефиса |
| Служебная метка `[bracketed]` | 106 | 0.04% | шум MFA, исключается при обучении |

**Примечание про метку spn:**
Метка spn встречается в 2 249 токенах (0.9%) — это случаи, когда MFA не смогла определить фонемы. Среди них:

106 токенов — служебная метка [bracketed] (шум в аудио),

2 143 токена — реальные слова, которых нет в MFA-словаре или которые aligner не смог разметить: редкие заимствования (юргенс, ригал), обсценная лексика (пьянки‐хуянки), аббревиатуры (чк‐гпу‐кэгэбэ), слова с открывающей скобкой ((в, (она), нормальные русские слова (бесчинствуют, её, жизни).

Решение: все токены с phones = spn исключаются из обучающей выборки и из подсчёта PER (согласно заданию). При inference такие токены обрабатываются OOV-модулем G2P — модель должна предсказать их произношение сама.

**Причины отбраковки 918 предложений:** наличие служебных меток MFA (`[bracketed]`, `spn`), слишком короткие предложения (1–2 слова), несовпадение нормализованного текста с исходной разметкой MFA.

**Вывод:** фильтр лабы 1 работает корректно. Все проблемные примеры (аббревиатуры, числа, латиница, сокращения) удалены на предыдущем этапе. Оставшиеся данные пригодны для обучения G2P; единственное, что требует внимания при подаче в модель, — **нормализация неразрывных дефисов** (`‐` → `-`).

**4.2 Неразрывные дефисы**

**2 090 токенов (0.85%)** содержат типографский дефис `‐` (U+2010) вместо ASCII-дефиса `-` (U+002D). Примеры: `что‐то` (216), `как‐то` (123), `какие‐то` (94), `все‐таки` (79), `кто‐то` (76), `из‐за` (43). Это нормальные русские слова, просто дефис в них — типографский символ.

**ASCII-дефисов всего 3** — все три токена (`селектрик-композер`, `татаро-монголъское`, `судебно-наказуемое`) имеют `phones = spn`, то есть MFA не смогла их разметить. Они покрыты фильтрацией `spn` (см. подраздел 4.3).

**Решение:** при подаче в G2P нормализовать дефисы — заменить все варианты (`‐` U+2010, `‑` U+2011, `‒` U+2012, `–` U+2013, `—` U+2014, `−` U+2212) на ASCII-дефис `-`.

## 5. Омографы и ударение

Анализ `lexicon.csv`: из 41 131 слова только **671 (1.63%)** имеют 2+ произношения. Однако **настоящих омографов с разным ударением среди них крайне мало**:

| Слово | Вхождений в train | Варианты |
|---|---|---|
| `замок` | 3 | `z̪ a m ə k` (×2), `z̪ ɐ m o k` (×1) |
| `мука` | 4 | `m ʊ k a` (×3), `m u k ə` (×1) |
| `парить` | 1 | только `p ɐ rʲ i tʲ` |
| `пропасть` | 1 | только `p r o p ə sʲ tʲ` |
| `атлас` | 1 | только `a t̪ ɫ ə s̪` |

**Большинство «многовариантных» слов — не омографы:**

- **предлоги** (`с`, `в`, `из`, `к`, `про`) — варианты из-за озвончения, оглушения и редукции;
- **имена собственные** (`чмутов`, `гонзалес`, `фридмен`) — MFA генерирует варианты, не имея надёжного произношения;
- **сложные слова** (`лесобиржи`, `несколько`) — разное ударение и редукция.

**Корректность разметки.** MFA действительно различает омографы по контексту: в корпусе у `замок` есть оба варианта (`зАмок` и `замОк`). Однако таких случаев **единицы** (3 вхождения для `замок`, 4 для `мука`).

**Сравнение с MFA-словарём.** `russian_mfa.dict` содержит оба варианта для почти всех классических омографов, но **порядок рангов не всегда правильный**: например, для `звонок` rank 0 = разговорный `звОнок`, rank 1 = литературный `звонОк`; для `уже` rank 0 = разговорный `ужэ`. Поэтому в G2P **предпочтительно опираться на частоты из `lexicon.csv`** (реальный корпус), а не на ранги MFA-словаря.

**Влияние на PER.** Из-за крайней редкости омографов в корпусе (единицы вхождений на ~197 тыс. train-токенов) ошибки на них дают вклад **менее 0.01% к PER** — на два порядка меньше порога 0.025. Проблема омографов в данной задаче **незначительна**.

## 6. Решения по архитектуре G2P

На основе EDA приняты следующие решения:

1. **Основной lookup** — `lexicon.csv` (train, самое частое произношение).
2. **Fallback** — `russian_mfa.dict` (rank 0; учитывая, что порядок может быть неидеальным, для слов с несколькими вариантами берём вариант, наиболее частый в `lexicon.csv`, если слово там есть).
3. **OOV-слова** — собственная модель (правила + ML, обученная на train).
4. **Фильтрация `spn` и `<SIL>`** — при обучении и подсчёте метрик; `<SIL>` проходит через G2P без изменений.
5. **Нормализация дефисов** — все варианты (`‐`, `–`, `—`, `−`) приводятся к `-` при подаче в G2P.
6. **Разделение train/test** — строго по правилу `id % 5 == 0`; никаких test-данных при обучении словаря и модели.
