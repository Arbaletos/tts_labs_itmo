# Лабораторная работа №5. Сервис синтеза — отчёт

## 1. Схема конвейера
→ normalize()       лаба 1: TextNormalizer — нормализация текста
→ tokenize()        лаба 2: слово + пунктуация до следующего слова (формат label_raw)
→ insert_pauses()   лаба 2: PausePredictor (catboost) — вставка токенов <SIL><SIL>

Все модели загружаются один раз при инициализации TTSPipeline (~11 с), при запросах
загрузки нет. Замеры времени ведутся по этапам, сводная метрика — RTF.

### Что пришлось изменить/согласовать в интерфейсах работ №1–4

- Словари лабы 3 (tokens_phones.csv, mfa_dict.csv) перенесены в корневое data/ —
  оттуда их читает пайплайн.
- Выбор чекпоинта лабы 4: вместо sorted(rglob('best_model*.pth'))[-1] — приоритет
  best_model.pth (иначе брался не тот файл).
- Долготы (ː): G2P по правилам порождает геминаты (выезжая → ʐː, нечаянно → ɲː),
  которых нет в фонемном инвентаре модели (56 фонем). В to_phones() добавлено схлопывание
  ː — то же преобразование, что применялось к обучающим данным лабы 4.
- Длинные входы: позиционное кодирование ForwardTTS ограничено 5000 токенов, а фраза
  eval_09 даёт ~7000 фонем. Добавлено чанкование в __call__: вход режется на фрагменты
  ≤350 символов по границам с пунктуацией, фрагменты синтезируются независимо и
  склеиваются с тишиной 0,25 с.
- Контракты каркаса соблюдены: Unicode NFC, ключ словаря = нижний регистр без ударения,
  сквозной проход <SIL> через G2P.

## 2. Анализ качества вокодера

Проверка копи-синтезом (реальная запись RUSLAN → мел → вокодер), файлы
natural.wav, copysynth_hifigan.wav, copysynth_griffinlim.wav.

- Диапазон мела реальной записи: [-10.24, 0.50] — совпадает с ожидаемым для
  конфигурации вокодера (22050 Гц, 80 мел, fmax 8000, натуральный логарифм), т.е.
  аудио-конфигурация подтверждена.
- HiFi-GAN: звучит очень близко к оригиналу; заметно лишь лёгкое приглушение
  звонких согласных — вокодер обучен на английском LibriTTS и слегка «сглаживает»
  спектр чужого голоса. Критерий приёмки выполнен.
- Griffin-Lim (то, что использовалось в лабе 4): выраженное «бульканье» и
  металлический тембр — артефакты реконструкции фазы. Переход на нейросетевой
  вокодер даёт существенный прирост натуральности.
- Остаточное приглушение звонких — аргумент за дообучение вокодера на RUSLAN
  (допзадание 2, вне объёма работы).

## 4. Анализ качества тракта на тестовых примерах

| Файл | Слуховые впечатления | Причина |
|---|---|---|
| eval_01 | треск на фоне; «съели все» вместо «всё» | артефакт модели; омонимия все/всё не разрешается словарным G2P |
| eval_02 | треск; нет вопросительной интонации | FastSpeech2 не моделирует интонацию вопроса; обучение на спокойном чтении RUSLAN |
| eval_03 | треск; неразборчиво | имена ацтекских богов — OOV, транскрибируются по русским правилам |
| eval_04 | металлический голос; «компью́тыре»; неверная мягкость согласных | редкие слова вне лексикона (0.91% токенов без транскрипции при загрузке) |
| eval_05 | треск; неестественная интонация; затянутая пауза в конце | предиктор длительностей на границе фразы |
| eval_06 | темп плывёт (медленно → быстро); странное «б» в начале | скороговорка вне распределения обучающего корпуса |
| eval_07 | низкая разборчивость + треск | редкое слово «зальцбург» |
| eval_08 | треск {TODO: как прозвучали fabric/details — проглочены/прочитаны по-русски?} | латиница вне G2P |
| eval_09 | треск; частые ошибки ударения; «бульканье» на стыках фрагментов | длинный вход: словарь не знает гоголевскую лексику; границы чанков режут контекст |
| eval_10 | треск; пауза отсутствует | без запятой предиктор паузу не ставит — смысловая неоднозначность не разрешается |

Системные выводы:

- *Треск на всех фразах* — артефакт акустической модели (ран lr5e3), а не вокодера:
  копи-синтез через HiFi-GAN на натуральном меле чистый.
- *Ударения и редкие слова* — главное ограничение словарного G2P: слово вне словаря
  транскрибируется по правилам без гарантии ударения; омонимы (все/всё) не разрешаются
  по контексту.
- *Просодия* (вопросительная интонация, темп) ограничена возможностями FastSpeech2
  и спокойным стилем корпуса RUSLAN.
- *Чанкование* спасает длинные входы, но границы фрагментов слышны (сбой, похожий
  на бульканье): модель начинает каждый фрагмент без левого контекста.

Модификации входных текстов не потребовались: все фразы подавались как есть.
Единственная адаптация — внутренняя (схлопывание ː и чанкование), текст не менялся.

## 5. Поведение на входах, которые тракт обработать не может

- Пустая строка / строка без слов → возвращается пустой wav, ошибки нет.
- Фонемы вне инвентаря → явный ValueError со списком неизвестных фонем
  (поймано на геминатах с ː при отладке).
- Долготы (ː) → схлопываются до обычных фонем, синтез продолжается.
- Входы длиннее 5000 фонем → автоматическое чанкование, синтез по фрагментам
  (ранее — падение с ошибкой PositionalEncoding).
- Теги разметки <pause type="normal|none"> → снимаются до нормализатора
  (символы </> иначе выбросил бы нормализатор), превращаются в запросы к
  вставке/подавлению <SIL>.
- Ни один из 10 тестовых входов сервис не роняет — критерий «делает хоть что-то»
  выполнен для всех примеров.
